# Relatório — Capítulo 0.3 (novo): Pydantic na prática

## Inventário

| Unidade | Símbolos cobertos | Exemplo (modulo-00/codigo/) |
| --- | --- | --- |
| `BaseModel` e `Field` | `BaseModel`, `Field` (`default`, `gt`, `ge`, `le`, `min_length`, `description`), `ValidationError` (`error_count`, `errors`, `loc`/`type`/`msg`) | `pydantic_modelo.py` |
| Entrada de dados | `model_validate`, `model_validate_json` (`.model_validate`, `.model_validate_json`), erros `greater_than` e `json_invalid` | `pydantic_entrada.py` |
| Saída de dados | `model_dump`, `model_dump_json`, `.model_copy` (com armadilha: `update` não valida) | `pydantic_saida.py` |
| Esquema JSON | `model_json_schema` (`.model_json_schema`), `description` e docstring no esquema | `pydantic_esquema.py` |
| Por baixo do PydanticAI | `output_type`, ferramenta de saída, `ValidationError` → `RetryPromptPart` → nova tentativa | `pydantic_por_baixo.py` (`FunctionModel`) |
| Regras próprias | `field_validator`, `model_validator(mode="after")` | `pydantic_validadores.py` |
| `TypeAdapter` | `TypeAdapter`, `.validate_python`, `.validate_json`, `.dump_python`, `.dump_json`, `.json_schema`; ligação com `ModelMessagesTypeAdapter` | `pydantic_type_adapter.py` |

Todos os 7 exemplos rodam offline (Pydantic puro e `FunctionModel`); as saídas no texto são as reais (pydantic 2.13.5, pydantic-ai-slim 2.54.0).

## Lacunas encontradas

| Lacuna | Onde aparecia sem explicação |
| --- | --- |
| `BaseModel`/`ValidationError` apresentados só de passagem | Capítulo 0.1 (`ecossistema_pydantic.py`) |
| Origem do esquema que o modelo recebe e do ciclo de nova tentativa | `output_type` nos módulos de orquestração |
| `TypeAdapter`, `.dump_json`/`.validate_json` usados para histórico de mensagens | capítulos de persistência e memória |

Capítulo inteiro (novo): 6 unidades `##` (mais a subseção "Por baixo do PydanticAI"), 3 armadilhas, 13 exercícios (0.3.1–0.3.13), Recapitulando com ponte para o 0.4 e Fontes. ~3.370 palavras contando o código.
